# Backup Rules

Back up the project before migration work.

## Keep Multiple Copies

Keep:

- a GitHub copy
- a local copy
- a Google Drive or external ZIP backup

## Before Big Changes

Before changing routing, loaders, or content storage:

1. Copy the working project folder.
2. Save a ZIP backup.
3. Confirm the current website still opens.
4. Then start migration work.

## Do Not Delete Old Working Files Too Early

Do not delete old working files before testing the new content system.

Keep `js/data.js`, `js/data-official-patch.js`, and the existing HTML pages until the new system is fully tested.
